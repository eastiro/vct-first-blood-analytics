## 二、我参考的具体案例

### 1. Steam Charts 重设计（Shakuro，Dribbble）

<https://dribbble.com/shots/26780155-UI-UX-Website-Redesign-for-Steam-Charts-Game-Analytics-Platform>

这段描述几乎就是我们这个页面要解决的问题：**「把结构感和层级带进高密度数据集」**。
具体做法是低对比暗色减少长时间阅读疲劳、分层卡片制造深度、用加粗文字和颜色高亮趋势。
→ 借了：分层卡片（panel / panel2 / panel3 三档明度）、单一高亮色。

### 2. HLTV.org 改版

<https://www.hltv.org/news/20530/a-new-beginning-for-hltvorg>

CS 数据站的标杆。改版说明里提到三件对我们有用的事：**首列作为上下文导航**、
**夜间模式**、**信息密度优先**。另外这家站基本不做动效——数据页的动效是负担。
→ 借了：零动效、密度优先、表头吸顶。

### 3. Gaming Dashboard UI Design（WANDR 工作室）

<https://www.wandr.studio/blog/gaming-dashboard-ui-design>

这篇把「游戏看板」的设计问题讲得最准，三个可以直接用的判断：

- **纯黑 #000 是错的**。暗色靠「变亮」表达层级，底如果已经是黑的就没法再往上抬。
- **暗色上要降饱和**。霓虹色在暗底上会边缘振颤，看十分钟没事，看两小时很累。
- **密度不是敌人，「没有差别的密度」才是**。用户是主动来看数据的，不该被删到只剩四个大数字；
  要做的是把层级拉开——一个明显的主数字，一层上下文，一层细节。

→ 借了：底色 `#0a1218` 而不是纯黑、强调色降饱和、KPI 里指定一个 hero 数字。

### 4. 2026 SaaS Dashboard 趋势

<https://dev.to/thekitbase/saas-dashboard-design-trends-in-2026-with-examples-121m>

几条和我们直接相关：dark-first、语义化色票（换 6–8 个变量就能换肤）、
**少装饰多数据**（卡片内边距收小、用 1px 描边替代阴影、圆角 2–4px）、
**彩色图标网格已过时**（单一强调色，颜色只留给状态）。

→ 借了：1px 发丝边 + 4–6px 圆角、去掉所有阴影、颜色只表达状态（红=负向、金=国际赛事）。

### 5. 看板字体与数字排版

<https://madegooddesigns.com/best-fonts-for-dashboards/>

最关键的一条：**表格和 KPI 必须开等宽数字（tabular figures）**，
否则数字一变化整列宽度就在抖，扫读成本极高。字体推荐 Inter（正文）+ 等宽（数字）。

→ 借了：Inter 正文 + JetBrains Mono 数字，全部 `font-variant-numeric: tabular-nums`。
字体已自托管到 `site/fonts/`（2 个 woff2，78 KB），不依赖 Google CDN——国内经常打不开。

### 6. 产品对照：Leetify / RIB.GG / VLR.gg

- **Leetify**（leetify.com）：把评分拆成 Aim / Utility / Positioning 三个维度，配雷达图和赛后报告卡
- **RIB.GG**（rib.gg）：Match Prep + Round Explorer + 2D 回放，我们做的球探报告和它同形态
- **VLR.gg**：队伍缩写 chip、超密表格、几乎零装饰

→ 借了：队伍缩写做成 chip（VLR 的做法）、报告页「结论先行 + 证据在后」的结构。

## 三、落到代码里改了什么

### 参考站实测（2026-10-26 抓取，`figures/_ref/` 有截图与 `probe.json`）

用 Playwright 直接打开各站取 `getComputedStyle`，不是凭印象：

| 站点 | 定位 | 页面底色 | 卡片 | 强调色 | 明暗 |
|---|---|---|---|---|---|
| **VLR.gg** | 瓦数据门户（我们的数据源） | `#C6C6C6` | `#FFFFFF` | 蓝链接 `#3A6EA5` | **浅色**（深色只是 Night mode 开关） |
| **RIB.GG** | 瓦球探工具（同形态竞品） | `#03101C` | `#16232E` | 紫 `#8B5CF6` | 深色 |
| **Leetify** | CS 个人表现分析 | `#19171E` | `#242230` | 洋红 `#E8365D` | 深色 |
| **Liquipedia** | 百科 | `#F5F5F5` | `#FFFFFF` | 蓝 | 浅色 |

HLTV / Tracker / EsportsCharts 被 Cloudflare 挡了（403），没取到实测值，按公开印象它们也是浅色。

**规律**：
- **数据门户**（VLR、Liquipedia、HLTV）几乎都是浅色——信息量大、要长时间扫读、多在白天看。
- **分析工具**（RIB、Leetify、Tracker）几乎都是深色——强调沉浸、看单场报告、常在晚上用。

我们两个页面各占一半：主站是门户，球探页是报告。最后统一走**浅色**，
因为「分析师」岗的交付物更像门户 + 打印报告，不是游戏 HUD；而且数据源 VLR 本身就是浅色。

### 色板（`site/index.html` 与 `site/scout.html` 共用一套）

```
--bg      #EAE7E0   暖纸灰（页面底，比纯白暖，长时间看更舒服）
--panel   #FFFFFF   卡片
--panel2  #F5F2EC   卡片内的次级块
--line    #DBD5C9   1px 发丝边
--line2   #C3BDAF   更重的分隔线（表头下沿）
--fg      #1B1A17   正文（不用纯黑）
--dim     #6B6862   次要文字
--dim2    #9B968C   标签 / kicker
--red     #DE3B49   唯一的强调色（比 #FF4655 略深，白底上更稳）
--cyan    #0E7C74   只给「防守方」这一条数据线
--gold    #A5741C   只给国际赛事（大师赛 / 冠军赛）
--green   #157F3B   正向变化
--amber   #B45309   警示
```

两条硬规则：
1. **选中态用墨黑，不用红。** 红只留给数据（KPI、数据条、负向变化），
   否则整页全是红，强调就没有意义了。
2. **底色必须明显比卡片深**（`#EAE7E0` vs `#FFF`），否则卡片浮不起来，整页会显得发灰。

### 排版

- 正文 Inter 13px；数字 JetBrains Mono + `tabular-nums`
- 标签做成 kicker：10px、大写、字距 .1em、`--dim2`（中文不用大写，只靠字距和灰阶）
- 层级靠字重和明度，不靠字号堆叠

### 结构

- **顶部**：eyebrow（赛事全称）→ 标题 → 一行数据范围；右侧 KPI 条，中间那个（首杀→胜率）标红
- **筛选条吸顶**：滚动时一直可见（手机上关闭，否则一屏被吃掉一半）
- **分区标题**：左侧 3px 红色短竖线 + 标题，替代原来的纯文字
- **表格**：行高约 44px、发丝分隔线、表头吸顶、首杀率列加了「轨道 + 填充」的行内数据条
- **三张宽表全部移到整页宽度**：各赛事对比、队伍对比、赛段对比；左右两栏只留地图和交易面板，高度正好配平
- **赛段面板**：左边三张数、右边解读文字，避免整行留白

### 没做什么（有意克制）

- 没有渐变背景、玻璃拟态、发光边框、粒子动效
- 没有给每个卡片配一个彩色图标
- 没有为了「好看」删掉任何一列数据——密度是这个页面的价值

## 五、交互层：按 Developer Award 的六个轴来做

Awwwards 的 **Developer Award** 是对拿到 Site of the Day 的站再做一次技术评估，
分六轴：可读性、动效、无障碍、速度、响应式、语义化标记。
公开统计里 393 个获奖站的均分是这样的：

| 轴 | 均分 | 读法 |
|---|---|---|
| 动效 motion | **7.80** | 最高——获奖站普遍舍得在动效上下功夫 |
| 速度 / 响应式 | 7.47 | 合格线，不拉开差距 |
| **无障碍 accessibility** | **6.82** | **最低**——这是最容易拉开差距的地方 |

另外总评分里 **Usability 占 30%，比 Creativity（20%）还高**。
所以「技术力」不等于 3D 和满屏动效，而是：**交互真的有用、键盘能用、动效克制**。

这个页面按这个标准做了五件事：

### 1. 命令面板（按 `/` 或 `⌘K`）

一只键盘就能跳到任意队伍 / 赛事 / 地图 / 英雄，不用去点三行筛选条。
Esc 关闭、↑↓ 选择、回车跳转，焦点会还给打开前的元素。
搜索按「完全匹配 > 前缀 > 包含 > 副标题包含」打分。

### 2. 筛选写进地址栏 + 一键复制链接

`?ev=VCT+Pacific+Stage+2&map=Sunset&team=...`
刷新不丢筛选，也能把「霓虹 + 微风岛屿」这样的具体视图直接发给别人。
球探页同样支持，报告可以整条链接发给教练。

### 3. 排序时的行位移动画（FLIP）

点表头排序时，行不是瞬间跳位，而是从旧位置滑到新位置。
实现是先记录每行的 `getBoundingClientRect().top`，重排后反向 `translateY` 再过渡回 0，
动画结束清掉内联样式（否则会拖累后续 hover）。

### 4. KPI 数字滚动

数值变化时 420ms 缓动过渡，用三阶缓出。
**首屏不播**——DOM 里已经是最终值，从 0 数上去反而闪。

### 5. 无障碍

- 跳转链接（Tab 第一下出现「跳到主内容」）
- 全局 `:focus-visible` 2px 红环，键盘用户看得见焦点
- KPI 区 `aria-live="polite"`，筛选变化会被读屏播报
- 命令面板 `role="dialog" aria-modal="true"`，列表 `role="listbox"/"option"`
- 所有动效都在 `prefers-reduced-motion: reduce` 下关闭

### 刻意没做的

- 没有页面进场大动画、没有滚动视差、没有 WebGL
- 表格行不做逐行 stagger（每次筛选都会重放，反而干扰读数）
- 不做「数字从 0 滚上来」的首次加载效果（同上）

## 六、去模板化（2026-10-27）

详细的参考站截图与逐条对照在 **`DESIGN-REFS.html`**（独立页面，浏览器直接打开）。
这一节只记结论和规则。

### 判断标准

> 判断一页是不是 AI 做的，不看配色，看它**敢不敢让某些地方空着、让某些地方更重**。
> 全页均匀 = 没有判断 = 机器。

抓了 40 个页面实测（脚本 `37/38/39_refs_capture*.py`，截图 `figures/refs/`）。
最值得反复看的是 **Plausible 的公开看板**（`plausible.io/plausible.io`）——
真实产品、和我们的结构同构、不需要登录。

### 六条硬规则

1. **一个逻辑块一个框，框内不再套框。** 内层分隔用 1px 发丝线，不加第二个边框。
2. **筛选不用药丸。** 下划线 tab（选中 = `inset 0 -2px 0`）或原生 `<select>`。
3. **比例条画在单元格背景里**，数字压在条上；不要「数字 + 下面一根装饰线」。
4. **一个页面只有一个强调色承担一个含义。** 红色只表示「负向 / 需要注意」，
   不再兼任品牌色、选中态、装饰色。
5. **不要大写字距的英文微标签。** 中文界面里那层「设计感」最廉价且不提供信息。
6. **不为显高级加交互。** 命令面板已删；数字滚动只在数值真变时播。
7. **一页只能有一个主角。** 目前是补枪效应：全宽、第一屏、两条等比横条。
   其余板块同级，靠位置和面积区分，不靠加大字号。
8. **窄屏筛选默认收起。** 手机上一整块筛选会占掉半屏，收成一行摘要更像工具。
9. **只陈述，不建议。** 数据页的每条结论只写「发生了什么 + 基准是多少」，
   不写「所以你应该怎么打」。替读者下结论是这类页面最明显的 AI 痕迹：
   它总是把一句统计翻译成一句看起来专业的战术建议，而那些建议往往经不起推敲
   （典型反例：「别指望靠人数劣势的残局翻盘」——没有人会这么指望）。

### 刻意保留的「不均匀」

- 三张宽表（赛事 / 队伍 / 赛段）全宽，左右两栏只放地图和补枪面板 → 高度配平，
  且表格列宽够用。这是**功能性**的不均匀，不是装饰。

### 2026-10-27 第二轮：确立主角 + 压缩筛选

- **补枪效应提为全宽主角**（`.panel.hero`）：两个胜率画成按 0–100 铺的横条，
  长度差直接等于差距。原来右栏三个数字无法互相比较。
- **筛选 231px → 157px**：33 个英雄 chip 改下拉，队伍与英雄并一行，「指标说明」靠右。
- **窄屏 532px → 42px**：`#fbody` 默认收起，只留「赛事 · 地图 · 队伍」摘要。
- **队伍报告的赛事/地图按队伍过滤**：PRX 从 15 个赛事降到它真打过的 6 个；
  换队伍时非法选中项自动回落。

### 2026-10-27 第三轮：阵容时间轴

- **「阵容指纹」→「阵容 · 按赛事」**：每行一个赛事（按时间从上到下），
  行内堆叠条 = 该赛事里各阵容的份额，取最常用的 6 套着色，其余合并成一块浅灰。
  右侧仍是该赛事的胜率与回合数。悬停看阵容与占比。
- **锁定单个赛事时行维度自动切成地图**，否则时间轴只剩一行没有意义。
- 中国赛区没有阵容数据 → 该行画斜纹 + hover 说明，但胜率照常显示（不需要阵容数据）。
- 灰色「其他」通常占 55–60%：这是真实分布（PRX 一季用了 43 套阵容），
  不是 bug，note 里写清楚灰是什么。
- 诚实边界：数据只到赛事粒度，**没有补丁日期**，所以「版本更替」只能讲到这里。

### 已知未解决

- 表格整列底色只做在队伍报告的队伍表上（首杀率用中性灰阶、首杀→胜用绿/红发散），
  赛事 / 赛段表还没做。

## 七、去 AI 味（2026-10-31）

一次纯减法：**只删和改，不加新东西**。截图对比在 `figures/deslop/`。

### 改了什么

1. **字号从 14 种收到 4 种**：`10 / 12 / 13 / 19`。
   原来是 8.5、9、9.5、10、10.5、11、11.5、12、12.5、13、13.5、18、19、20、21、23、27，
   靠半个像素区分层级，等于没有层级。层级靠字重、颜色和间距拉开就够了。
   最小 10px（原来有 8.5px 的 `?` 上标和 9px 的队标 chip）。
2. **圆角从 10 种收到 3 种**：`0 / 4px / 6px`（加队标、圆形除外）。
   10px 的面板圆角是「模板卡片」的典型特征；`scopebtn` 和 `glossbtn` 原来的 20px / 15px 药丸已去掉。
3. **页签选中态从红改成墨黑**。原来红线 + 红标题 + 红数据条 + 红色分区竖线，
   一页里有四处红在抢注意力，红色就不再是「需要注意」的信号。
4. **删掉所有装饰性阴影、毛玻璃、渐变底色**：
   - scout 页 `body` 上那层 `radial-gradient` 粉色光晕
   - 两页 header 的 `backdrop-filter: blur(10px)`
   - 提示卡和 tooltip 的 `box-shadow`
   - 地图打点原来先画径向渐变再 `lighter + blur` 叠一层发光——密度本身就能看出热区，
     发光只会糊掉边缘
5. **文字前面的序号去掉**：队伍报告「可利用倾向」原来的 `1 2 3`、总览排行榜原来的 `1 2 3 4 5`。
   榜单已经按数值降序排，序号不提供新信息。
6. **排行榜的比例改成单元格底色**（`td.barcell`）：原来「数字 + 下面一根装饰线」，
   现在是色条当底纹、数字压在条上。这段 CSS 早就写好了一直没用。
7. **药丸式按钮全部改成文字 + 下划线**：「复制链接」「导出 PDF」「本赛事」「指标说明」，
   以及 scout 页的数据覆盖徽章。徽章只在真的缺数据（无坐标 / 样本偏小）时才出现，
   「阵容池 545 套」这种常驻信息已删。
8. **重复的说明删掉**：
   - 总览页地图面板下方那条黄色「数据说明」框（页脚已写同一件事）
   - 「全部地图」模式下表格上方的标题 + 「点任意一行」提示（面板标题已经说明）

## 八、删掉 eco 局胜率（2026-11-03）

用户问「eco 局的定义到底是啥」，查完发现这个档的定义撑不住它自己的名字：

| 实测 | 数 |
|---|---|
| 叫 eco 的队伍-回合 | 11,773 |
| 其中 0 把长枪 | 9,500（80.7%） |
| 0 长枪但 ≥4 把 Stinger / Spectre | 1,407（占 eco 档 12.0%） |
| 0 长枪但全队花了 8,000 以上 | 占 0 长枪的 6.9% |

分档规则是「长枪把数 ≤1 / 2–3 / ≥4」，`LONG_GUNS` 里只有 8 把步枪和狙击，
没有冲锋枪。所以 **5 把 Vandal 是强起，5 把 Stinger 是 eco** —— 同一个战术意图
被判成两端。典型组合：

```
5 stinger            14 次
4 stinger + classic   7 次
4 spectre + judge     5 次
```

一个把强起也算进去的档，它的胜率说不出「省钱的回合有多难赢」。所以整条删掉，
不留降级版本。同时删掉：

- `CAT_ORDER` 里的 `'eco 局': 9`
- `TERMS` 里的 `'eco 局'` 词条（悬空的定义本身就是噪音）
- `baseline()` 的 `b.econWin` / `b.econShare`，只留 `b.fullWin`（`econShare`
  是经济面板删掉后就没人用的死代码）
- `TERMS['全买局']` 原来靠「eco 局是 ≤1 把，中间那档是半买」来解释自己，
  改成自洽：直接写 ≥4 把，并把长枪名单列出来

**留了什么**：全买局胜率（≥4 把长枪，占 68.9% 的回合）保留。这一档定义干净，
而且 4 把和 5 把都是同一件事——正常买枪。

**教训**：`spent` 不能用（留枪记 0 花费），这是对的修正；但换成「长枪数」之后
档位的**名字**没跟着改。`eco` 是个有明确含义的战术术语，用它当「≤1 把长枪」的
标签，等于承诺了一个定义没兑现的东西。分档的时候，名字和规则要么一起定，
要么就别用行话。

## 九、阵容面板加时间轴（2026-11-03）

用户要「按时间轴排，看不同版本阵容有什么变化」，并说「不需要非常准确」。

**直接按赛事排会骗人。** 阵容是按地图选的，一套只打某张图的阵容，
在没打这张图的赛事里自然显示 0%。实测 PRX 前 6 套在相邻赛事之间整段跳到 0.0%：

```
阵容      koff 2026  圣地亚哥  太平洋S1  伦敦  太平洋S2  冠军赛
#1          13.7%    24.7%     0.0%    0.0%   11.3%   18.3%
#2           0.0%     0.0%    19.3%   21.7%    0.0%    0.0%
#3           0.0%     0.0%    17.0%   25.9%    0.0%    0.0%
```

看上去像「阵容大换血」，其实是赛程里没有那张图。这个图会直接误导
「版本变化」这个唯一目的。

**所以行维度跟着地图选择器走**：

| 范围 | 行 | 标题 |
|---|---|---|
| 全部地图 | 一张图一行，按回合数排 | 阵容 · 按地图 |
| 选定一张图 | 一个赛事一行，按时间先后排 | 阵容 · 按时间 |

同一张图上按时间排就干净了——PRX 莲华古城 4 个赛事 4 套阵容，
每套都是 100%，换版本换得干干净净：

```
VCT 太平洋 第一赛段   捷风·幽影·雷兹·斯凯·维斯 68.5% + 黑梦·霓虹·幽影·雷兹·维斯 31.5%
伦敦大师赛 2026       捷风·幽影·雷兹·斯凯·维斯 100%
VCT 太平洋 第二赛段   黑梦·幽影·雷兹·蝰蛇·夜露 100%
上海全球冠军赛 2026   黑梦·幽影·雷兹·维斯·夜露 100%
```

**配色规则也跟着变**：按地图时每张图给自己的前 4 套补色（允许撞色）；
时间轴只按全局前 6 套上色，**同一套阵容在所有行必须同色**——否则看不出走势。
`94_verify_scout.py` 加了一条断言专门守这个。

**顺手修的**：430px 下 `.vcmp`（基准那行等宽字）是 `nowrap`，把整页顶出去 29px
（`scrollWidth 459 / clientWidth 430`）。窄屏改成 `white-space:normal`。
这个溢出在改阵容之前就有，不是这次引入的。

**行尾少一个列头（同一天，用户问「这个又是啥」）**：行尾的 `53.8% · 461`
和图例的 `11.2% · 269 回合` 长得几乎一样，前者是该队这行的胜率、回合数，
后者是某套阵容的份额、回合数。没有列头，读者只能猜。

补了一行 10px 的淡色列头：左边写行维度（`地图` / `赛事`），右边写 `胜率 · 回合`。
行维度接近行标签、胜率远离行标签，列头把这个不对称补上了。
